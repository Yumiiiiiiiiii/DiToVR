# 構成の変更点（内部整理）

現行の構成そのものは [ARCHITECTURE.md](../../ARCHITECTURE.md) にまとめています。ここには、内部整理で変わった点と、守るべき非同期実行の規則だけを記録します。

## 非同期実行の規則
- `Runtime::execute` / `apply_*` は内部で `block_on` するため、**どの Tokio ランタイムのタスク上でも直接呼ばない**。UI の背景スレッドか `spawn_blocking` から呼ぶ（`update.rs` の `call_host`）。
- 更新の `busy` は `BusyGuard`（Drop）で解除し、失敗・panic でも残さない。
- 更新サーバーの応答は署名検証の前に上限を設ける（フィード 1 MiB、インストーラー 200 MiB）。
- 更新を中止したときは、更新前に動いていた受信だけを再開する。インストーラー起動の直前に、設定の編集が始まっていないかを再確認する。

## 変更点
- 通知の重複 ID は、自分の投稿・空本文の判定を通った後に記録する（空イベントが ID を消費しない）。
- PING への PONG 書込は、受信期限の残り時間（最低 250 ms、最大 5 秒）で打ち切る。
- VR ワーカーは、外部の送信側が全て閉じたら（接続中・再接続待ちとも）終了する。
- 旧保存先の更新設定は、`Updater` が読む前に移行する。
- 認証情報の復号は `decode_secrets` に集約し、検証つき読込と設定画面用の読込で共有する。
- Gateway の HELLO 解釈・Close コード分類・再試行待ちを小さな関数に分けた。
